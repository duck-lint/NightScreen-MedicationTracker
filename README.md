# RedPillz

RedPillz is a small local-first Android utility app built for a Pixel-first workflow. This first pass fully implements pill dose logging and includes a real, bounded system-wide red overlay feature path using Android overlay APIs instead of an in-app fake.

## Architecture Summary

- Kotlin + Jetpack Compose UI with shallow bottom navigation.
- Simple MVVM with an `Application`-level `AppContainer` instead of a DI framework.
- Room stores medications and dose entries.
- DataStore stores overlay preferences such as enabled state and overlay alpha.
- A foreground `OverlayService` owns the full-screen `TYPE_APPLICATION_OVERLAY` red view.

## First local setup on Windows

1.  **Open in Android Studio**: Launch Android Studio and select **Open** to navigate to this project folder.
2.  **Install SDK and Tools**: Ensure you have **Android API 35 SDK**, **Build-Tools**, and **Platform-Tools** installed via the SDK Manager.
3.  **Configure JDK**: Use **JDK 17** for the Gradle build (Settings > Build, Execution, Deployment > Build Tools > Gradle > Gradle JDK).
4.  **Sync Project**: Click **Sync Project with Gradle Files**.
5.  **Generate Gradle Wrapper**: Open the terminal in Android Studio and run `gradle wrapper`. This will generate the necessary `gradlew`, `gradlew.bat`, and `gradle/wrapper/` files locally. **Do not fabricate these files; they must be generated by a real Gradle environment.**
6.  **Commit Wrapper**: Once generated, commit the `gradlew`, `gradlew.bat`, and `gradle/wrapper/` files to your local repository.
7.  **Run**: Connect a USB-debuggable Pixel device (API 29+) and run the `app` configuration.

## What Is Fully Implemented

### Pill logging

- Quick-add logging from Home with medication selection and dosage in mg.
- Full Pill Log screen with manual date/time editing, optional notes, edit, and delete.
- Today’s entries and grouped totals update from Room-backed data flows.
- Minimal medication management in Settings: add, rename, archive, reactivate.

### Overlay

- Real overlay permission flow entry point using Android overlay settings.
- DataStore-backed overlay enabled state and alpha.
- Foreground `OverlayService` with `android:foregroundServiceType="specialUse"`.
- `android.permission.FOREGROUND_SERVICE_SPECIAL_USE`.
- Service property `android.app.PROPERTY_SPECIAL_USE_FGS_SUBTYPE="user-controlled full-screen red light reduction overlay"`.
- Non-touchable full-screen red overlay via `WindowManager.TYPE_APPLICATION_OVERLAY`.
- Overlay start kept user-controlled and limited to visible in-app UI in v1.

## What Remains Bounded / Honest

- The overlay is real, but not treated as universally omnipotent. Some Android system surfaces can still appear above it.
- No boot auto-start, no background self-restart, and no claim that Android will always deep-link directly to the app-specific overlay permission page on Android 11+.
- The app does not add reminders, sync, accounts, analytics, health integrations, or internet access.

## Manual Test Checklist

### Core pill logging

1. Launch the app and open `Settings`.
2. Add at least one medication.
3. Return to `Home`, quick-log a dose, and verify it appears immediately in today’s entries and totals.
4. Open `Pill Log`, add another dose with a manual timestamp.
5. Edit an existing entry and verify the grouped total changes immediately.
6. Delete an entry and verify the list and total update immediately.
7. Archive a medication in `Settings` and verify historical entries remain visible.

### Overlay

1. Open `Overlay`.
2. Read the system-wide overlay messaging and the Android 11+ permission guidance.
3. Tap `Open overlay permission settings` and grant Display over other apps access.
4. Return to the app, enable the overlay preference, and start the overlay from the visible screen.
5. Leave the app and confirm the red overlay appears across other apps where Android permits it.
6. Stop the overlay from the app, then start it again and stop it from the notification action.
7. Revoke overlay permission and confirm the UI reports the permission loss honestly.
